# Low-End Lock — 产品需求文档

## 1. 文档信息

- 版本：v1.0
- 状态：Draft
- 关联文档：TRD、DSP Architecture、UX/UI Spec、Test Plan

## 2. 产品目标

### 2.1 问题陈述

Kick 与 Bass 在低频段重叠时，常因极性与时间差造成相位抵消，导致低频能量损失。现有解决方案过于复杂，用户缺少一个即时、直观、结果可量化的工具。

### 2.2 产品目标

提供一个实时插件，使用户能够：

1. 将 Kick 作为 sidechain 参考。
2. 将 Bass 作为主信号。
3. 点击一次 `Lock`，自动选择最佳极性与时间补偿。
4. 看到并听到低频抵消被修复的程度。

### 2.3 非目标

- 不做自动混音。
- 不做 AI 音色生成。
- 不做全频段多轨对齐。
- 不提供云端处理。

## 3. 用户画像

### Persona A：电子音乐制作人 Alex

- 25–35 岁，独立制作，使用 FL Studio / Ableton Live。
- 每天处理 Kick/Bass 关系。
- 不希望学习相位理论。
- 愿意为 20–50 美元的一次性工具付费。

### Persona B：混音师 Mia

- 30–45 岁，承接混音项目。
- 已有专业工具，但需要快速试错的轻量工具。
- 关注 CPU、延迟、可撤销、可信结果。

## 4. 用户故事

1. 作为制作人，我希望把 Bass 轨插入 Low-End Lock，并把 Kick 轨路由到 sidechain，以便插件知道参考低频信号。
2. 作为制作人，我希望点击 `Lock` 后，插件自动分析并应用最佳修复，以便我不需要理解相位。
3. 作为混音师，我希望手动调整 Polarity、Delay、Low Cut，以便应对自动检测失效的特殊素材。
4. 作为用户，我希望看到修复前后的 `Cancelation Saved`，以便判断插件是否有效。
5. 作为现场用户，我希望插件实时、低延迟、低 CPU，以便在演出中安全使用。

## 6. 非功能需求

### 6.1 音频性能

- 支持 44.1、48、88.2、96 kHz。
- 默认实时 CPU 占用目标：单实例 < 2%。
- 目标插件报告延迟：0 samples，或不超过 64 samples。
- 音频线程内无锁、无内存分配、无文件 IO。

### 6.2 平台

- macOS：AU、VST3。
- Windows：VST3。
- 后续：CLAP、AAX。

### 6.3 易用性

- 默认界面核心控件不超过 5 个。
- 主要流程不超过 3 步。
- 所有自动处理均可被手动覆盖。

### 6.4 可靠性

- 无输入时静音，无 NaN / Inf 输出。
- 参数变化平滑，无爆音。
- sidechain 缺失时给出清晰状态。

## 7. 关键用户流程

### 7.1 首次使用

1. 打开插件。
2. 将插件插入 Bass 轨。
3. 将 Kick 路由到插件 sidechain。
4. 播放包含 Kick 和 Bass 的片段。
5. 点击 `Lock`。
6. 观察 `Cancelation Saved`，使用 A/B 试听。

### 7.2 手动微调

1. 如果自动结果不佳，关闭 `Auto`。
2. 手动切换 Polarity。
3. 调整 Delay，直到低频最饱满。
4. 调整 Low Cut，控制处理频段。

## 8. 验收标准

### 8.1 MVP 发布门槛

- 所有 P0 功能可用。
- 通过客观 DSP 测试与基础感知测试。
- 通过 DAW 兼容性测试。
- 无阻塞性崩溃或爆音问题。
- 有用户手册 / 首次使用提示。

### 8.2 Beta 目标

- 至少 30 名真实用户试用。
- 获得至少 20 份有效反馈。
- 确认主要用户是否理解 `Cancelation Saved` 指标。

## 9. 假设与待确认问题

1. 假设用户愿意使用 sidechain 路由，而不要求插件自动分离 Kick/Bass。
2. 假设 `Cancelation Saved` 是用户可理解的指标，而不是仅展示相位角。
3. 假设 20–50 美元一次性定价适合目标用户。
4. 待确认：是否需要内置测试音源，帮助用户在没有 Kick/Bass 素材时体验。
