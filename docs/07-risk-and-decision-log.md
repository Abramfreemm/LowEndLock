# Low-End Lock — 风险、假设与决策日志

## 1. 风险登记

### R-01 市场已有成熟相位工具

- 等级：高。
- 影响：用户认为不需要新产品。
- 应对：不做全功能相位工具，聚焦一键低频修复和 `Cancelation Saved`。

### R-02 用户不愿意配置 sidechain

- 等级：中。
- 影响：首次使用流失。
- 应对：提供清晰的引导；未来可加入自动分离或双输入模式。

### R-03 自动检测在复杂素材上不可靠

- 等级：中。
- 影响：结果错误，信任下降。
- 应对：设置 confidence 阈值；不可靠时不做自动应用；保留手动覆盖。

### R-04 `Cancelation Saved` 指标被误解

- 等级：中。
- 影响：用户对效果预期错误。
- 应对：Beta 阶段验证文案；使用 A/B 与可视化辅助解释。

### R-05 分数延迟引入相位失真

- 等级：低。
- 影响：处理音质下降。
- 应对：选择合适插值/全通方法，做听感测试和群延迟验证。

### R-06 实时性能不达标

- 等级：低。
- 影响：无法用于现场或大工程。
- 应对：只处理低频，分析放后台线程，音频路径极简。

## 2. 假设登记

| ID | 假设 | 验证方式 |
|---|---|---|
| A-01 | Kick/Bass 相位抵消是目标用户共识痛点 | Beta 用户访谈、短视频评论 |
| A-02 | 一键操作优于全参数控制 | A/B 测试、可用性测试 |
| A-03 | 用户理解 dB 而不是相位角 | 早期原型访谈 |
| A-04 | 20–50 美元定价可接受 | 落地页价格测试 |
| A-05 | 目标用户主要使用 VST3/AU | 下载/反馈统计 |

## 3. 决策日志

### D-01 是否做全频段相位对齐

- 决策：MVP 不做。
- 理由：范围过大，且已有 InPhase、Auto-Align。
- 日期：2026-09-19。

### D-02 是否引入 AI

- 决策：不引入。
- 理由：MVP 复杂度、延迟、解释性风险高；低频互相关已足够。
- 日期：2026-09-19。

### D-03 是否引入 lookahead

- 决策：MVP 不引入。
- 理由：保持实时低延时；后续作为可选模式。
- 日期：2026-09-19。

### D-04 主信号与 sidechain 的定义

- 决策：主信号为 Bass，sidechain 为 Kick。
- 理由：Kick 通常作为时间参考，Bass 作为被补偿主体。
- 日期：2026-09-19。
