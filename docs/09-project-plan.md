# Low-End Lock — 项目计划与里程碑

## 1. 估算原则

以下为单人或 1–2 人小团队估算。假设开发者熟悉 JUCE 与实时 DSP。

## 2. 工作分解

| ID | 任务 | 依赖 | 预估 |
|---|---|---|---|
| T-01 | 冻结 PRD / TRD | 无 | 1–2 天 |
| T-02 | Python 参考算法 | T-01 | 1–2 天 |
| T-03 | 合成测试向量 | T-01 | 0.5 天 |
| T-04 | C++ DSP 核心 | T-02 | 2–3 天 |
| T-05 | 分析线程与状态管理 | T-04 | 1–2 天 |
| T-06 | JUCE Processor / Editor 骨架 | T-01 | 1 天 |
| T-07 | UI 单视图 | T-06 | 2–3 天 |
| T-08 | Sidechain 路由与状态提示 | T-04 | 1 天 |
| T-09 | 预设与参数系统 | T-06 | 1 天 |
| T-10 | 单元测试 | T-04 | 1–2 天 |
| T-11 | 性能优化与实时安全审查 | T-04 | 1–2 天 |
| T-12 | DAW 集成测试 | T-05 | 2–3 天 |
| T-13 | 主观听感测试 | T-12 | 1 天 |
| T-14 | 安装包、签名、文案 | T-12 | 2 天 |
| T-15 | Beta 发布 | T-14 | 1 天 |

## 3. 里程碑时间线

| 里程碑 | 内容 | 预估 |
|---|---|---|
| M0 | 文档冻结 | 第 1 周 |
| M1 | 算法原型 | 第 1–2 周 |
| M2 | MVP 内测版 | 第 3–5 周 |
| M3 | Beta | 第 5–7 周 |
| M4 | V1.0 | 第 8–10 周 |

## 4. 关键路径

```text
算法验证 -> C++ DSP 核心 -> 实时线程/性能 -> DAW 集成 -> Beta
                   \-> UI -> 预设/状态 -> 打包发布
```

## 5. 每周节奏

- 每周一：明确本周可交付结果。
- 每周五：客观测试 + 主观试听记录。
- 每次算法变更：先更新参考实现，再改 C++。
- 每个 DAW 集成问题：登记到风险日志。

## 6. MVP 完成定义

- P0 需求全部实现。
- 测试计划发布门槛通过。
- 可在至少 3 个目标 DAW 中正常使用。
- 有安装包、用户引导和反馈渠道。
